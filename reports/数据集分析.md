### 1.2 Abstract 清洗策略（缺失率 9.5%，远超 1% 阈值）

**缺失原因**：abstract 缺失主要由文章类型决定，而非数据质量问题。

```
correction(31) + editorial(30) + letter(24) + book-review(10) + ...
≈ 103/2000 = 5.2%（此类文章本身无摘要，属正常现象）
剩余 ~4.3% 为 research-article 自身缺失 abstract
```

**两阶段清洗流程**：

| 阶段 | 操作 | 说明 |
|------|------|------|
| 阶段 1 | **前置过滤** | 丢弃 correction / retraction / editorial / letter / book-review / news / reply |
| 阶段 1 | **保留** | research-article / review-article / systematic-review / case-report / brief-report |
| 阶段 2 | 有 abstract | 直接使用，标记 `abstract_source = "original"` |
| 阶段 2 | 无 abstract，有 body | 取 body 前 500 字作代理摘要，标记 `abstract_source = "body_fallback"` |
| 阶段 2 | 无 abstract，无 body | **丢弃**（无可检索内容） |

> 不建议直接丢弃全部无摘要文章——research-article 中缺 abstract 的文章正文通常完整，直接丢弃会损失约 4.3% 有效文献。

### 1.4 关键字段分析

#### journal — 可作为元数据过滤器，需名称标准化

- **完整率 100%**，字段本身完全可靠
- **主要问题**：同一期刊存在多种拼写变体，如 `"PLoS ONE"`（184 篇）与 `"PLOS One"`（13 篇）并存
- **数据集重要限制**：oa_comm 以商用 CC-BY 许可收录，《Nature》主刊极少出现；样本 Top 20 中仅有 `"Nature Communications"`（19 篇），主要来源为 PLoS、Frontiers、BMC、MDPI 等全 OA 出版商
- **结论**：可作过滤器，但"检索《Nature》文献"在本数据集命中极少，入库时需做期刊名标准化映射

#### pub_date / pub_year — 可作为时间过滤器

| 字段 | 缺失率 | 说明 |
|------|--------|------|
| `pub_date`（完整日期） | 0.0% | 500 篇实测 |
| `pub_year`（仅年份） | **0.0%** | 即使 pub_date 不全，年份总是存在 |

- 数据集时间跨度：**1840 年 — 2026 年**（含历史期刊数字化归档）
- "近 5 年"（2021–2026）在样本中约占 **34%**
- **建议**：将 `pub_year` 单独提取为 `int` 字段，直接支持 `pub_year >= 2021 AND journal == "Nature Communications"` 此类范围查询

#### pmid — 可作为溯源链接，需三级兜底

| 指标 | 500 篇实测 |
|------|-----------|
| pmid 存在 | 73.4% |
| pmid **缺失** | **26.6%** |

pmid 缺失常见于新发表文章（PMC 先于 PubMed 收录）或部分小型期刊。需配合三级降级链以保证 100% 有可点击链接：

| 优先级 | 字段 | 链接模板 | 覆盖率 |
|--------|------|---------|--------|
| 1 | `pmid` | `https://pubmed.ncbi.nlm.nih.gov/{pmid}/` | 73.4% |
| 2 | `doi` | `https://doi.org/{doi}` | ~94.8% |
| 3 | `pmc_id` | `https://www.ncbi.nlm.nih.gov/pmc/articles/{pmc_id}/` | **100%** |

### 2.5 语言风格与信息密度总结

| 维度 | 观察 | 对 RAG / 提示词的影响 |
|------|------|---------------------|
| 信息密度 | 单句常含 3–5 个专业术语或数值 | chunk 不宜过小，建议 ≥ 200 tokens |
| 缩写密度 | 每 50 tokens 约出现 3–5 个大写缩写 | 检索 query 需支持缩写扩展 |
| 同义词 | 同一概念存在多种表述（见下表） | 向量检索优于关键词精确匹配 |
| IMRaD 结构 | 正文几乎全部遵循四段式 | 可按章节分块以区分方法 / 结论 |
| 数值密集 | 大量 p 值、置信区间、样本量 | 评估时数值类问题需单独处理 |

**常见同义词对照**：

| 概念 | 常见表述 |
|------|---------|
| 心肌梗死 | myocardial infarction / heart attack / MI / AMI / acute coronary syndrome |
| 患者 | patient / subject / participant / case / individual |
| 显著 | significant / substantial / considerable / marked / notable |
| 死亡率 | mortality / death rate / fatality rate / case fatality |
| 随机对照试验 | RCT / randomized controlled trial / randomised trial |
| 肿瘤 | cancer / tumor / tumour / malignancy / neoplasm / carcinoma |
| 血压 | blood pressure / BP / hypertension / SBP / DBP |

> **提示词工程基线建议**：
> 1. 检索 query 应容忍缩写与全称等价（EGFR = epidermal growth factor receptor）
> 2. 评估答案时，同义词表述视为等价正确
> 3. 提示词中要求模型【用通俗语言解释术语】可降低幻觉风险
> 4. 数值类问题（剂量、p 值、生存率）需在评估中单独处理，不应模糊匹配

## 四、文本分割策略

> 依据前三节实测数据制定，嵌入模型 Token 上限：512

### 4.1 策略选择依据

| 策略 | 触发条件 | 本数据集情况 | 适用 |
|------|---------|------------|------|
| 整体不分割 | p95 < 512 | p95 = **560** > 512 | ❌ 不完全适用 |
| 重叠滑动窗口 | 存在长尾文档 | 8.4% 超出 512，max = 1912 | ✅ 适用于长尾 |
| 语义章节分割 | 有明确章节标题 | 正文 section 结构 ≈100% 清晰 | ✅ 适用于正文层 |

**决策树**：

```
输入文本
  ├─ 摘要（Abstract）
  │    ├─ ≤ 512 tokens（91.6%）→ 【策略 A】整体不分割
  │    └─ > 512 tokens（8.4%） → 【策略 B】重叠滑动窗口
  │
  └─ 正文（Body）
       ├─ 第一步：按 <sec> 标题语义切割
       └─ 第二步：对 > 512 tokens 的 section → 【策略 B】滑动窗口
```

---

### 4.2 策略 A — 整体不分割（摘要主体，91.6%）

| 条件 | 实测值 |
|------|--------|
| 摘要 ≤ 512 tokens 的比例 | **91.6%** |
| 中位数 | 323 tokens |
| p90 | 496 tokens（仍在 512 内） |

**Document 构造**：将 `"标题 + 摘要"` 作为一个完整 Document 直接入库。

| 优点 | 缺点 |
|------|------|
| 上下文最完整，检索精度最高 | 仅覆盖 91.6%，剩余需策略 B 补充 |
| 无需 Splitter，实现最简单 | — |

---

### 4.3 策略 B — 重叠滑动窗口（摘要长尾，8.4%）

| 条件 | 实测值 |
|------|--------|
| 超出 512 tokens | 8.4%（609 / 7248） |
| p95 | 560 tokens（仅超出 48 tokens） |
| p99 | 704 tokens |
| max | 1912 tokens |

**参数设定**：

| 参数 | 值 | 推导说明 |
|------|-----|---------|
| `chunk_size` | **400 tokens** | 上限 512 − title（~60 tokens）− 缓冲，约 400 |
| `chunk_overlap` | **80 tokens** | ≈ chunk_size × 20%，防止关键语句在边界割裂 |
| 分隔符优先级 | `"\n\n" → "\n" → ". " → " "` | 优先按段落 / 句子断，避免截断句子中间 |

> `length_function` 必须使用 tokenizer 计数，而非字符数 `len()`。每个分块均保留原始标题作为前缀，确保独立检索时有上下文。

---

### 4.4 策略 C — 语义章节分割（正文 Body）

| 条件 | 实测值 |
|------|--------|
| research-article 比例 | 75.8% |
| 正文 section 结构完整 | ≈100%（JATS `<sec>` 标签） |
| 单章节中位数 | 416 tokens |
| 单章节 p90 | **2003 tokens**（须二次切割） |
| 全文中位数 | 12,170 tokens |

**两阶段流程**：

| 阶段 | 操作 | 条件 |
|------|------|------|
| 阶段 1 | 按 JATS `<sec>` 标签切割，每个 section 成为候选 chunk | 所有正文 |
| 阶段 2 | 对超长 section 使用滑动窗口（同策略 B 参数）二次切割 | section tokens > 512 |

> 每个分块均保留所属 section 标题（如 `"Methods"`、`"Results"`）作为前缀，既保留语义上下文，也支持按章节类型过滤检索结果。

---

### 4.5 整体汇总

**每篇文章产生的 Document 数量估算**：

| 来源 | 策略 | 估算 chunk 数 / 篇 |
|------|------|-----------------|
| 摘要（≤ 512 tokens） | 策略 A | 1 |
| 摘要（> 512 tokens） | 策略 B | 2–4 |
| 正文各 section | 策略 C | 4–8（视期刊） |
| **合计（典型文章）** | | **5–9 chunks** |

| `pmc_id` | `"PMC3089640"` | 去重 / 溯源 |

### 4.6 部署注意事项

| 问题 | 处理方式 |
|------|---------|
| **Tokenizer 替换** | 上线前将 `cl100k_base` 换成目标嵌入模型的 tokenizer，`chunk_size` / `chunk_overlap` 小幅重校 |
| **Abstract 代理摘要** | 9.5% 摘要缺失，已用 body 首段填充；通过 `abstract_source = "body_fallback"` 字段区分 |
| **无正文文档** | 4.7% 无正文，跳过策略 C，仅保留策略 A / B 的摘要 chunk |
| **噪声文章过滤** | correction / editorial / letter 等已在入库前过滤，避免影响检索质量 |
| **多 chunk 合并** | 检索命中同一 `pmc_id` 的多个 chunk 时，按 `chunk_index` 排序合并后再传入 LLM |
